## Receiver deadline defect and design

The receiver has a configured SIGALRM deadline, but its exception handler cancels that alarm before writing a buffered error frame. An authenticated peer that stops reading can fill stdout and block that error write indefinitely. Interpreter shutdown can also flush buffered bytes to the same blocked pipe. The initial targeted regression uses a real pre-filled OS pipe, a one-second configured timeout and an immutable synthetic recovery point; it checks bounded exit, released catalog lock and absence of publication. No remote endpoint is contacted.

Keep the existing fixed receiver protocol, authentication/scope contract, publication guards and read/copy deadline. Replace only receiver output with unbuffered, nonblocking descriptor writes bounded by the original monotonic deadline. Never extend an expired deadline merely to return diagnostic metadata. A peer that is not reading may receive no error frame; source-side disconnect remains an ambiguous transfer outcome resolved by replaying the same sealed epoch. Successful publication remains governed by the exact manifest receipt. This is preferable to adding another timeout, buffering more data, or exiting with `os._exit` that bypasses normal lock/context cleanup.

Relevant primary references: [Python signal semantics](https://docs.python.org/3/library/signal.html), [nonblocking descriptors](https://docs.python.org/3/library/os.html#os.set_blocking), [poll readiness](https://docs.python.org/3/library/select.html#polling-objects). This change adds no CloudStack API/provider behavior and retains the pinned 4.22.1.1 native adapter unchanged.

Threat/failure boundary: a paired authenticated sender controls pipe progress and request bytes but not receiver configuration. The asset is receiver availability and exclusive catalog access. Scope/manifest checks and private staging remain mandatory. An interrupted epoch is never automatically discarded or published. A later retry reuses verified sealed data. Kernel-blocked storage calls remain outside the claim of a user-space I/O deadline.
