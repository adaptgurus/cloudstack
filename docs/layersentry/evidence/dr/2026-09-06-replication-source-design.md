# DC/DR replication source implementation

Status: `NOT_TESTED`. The user explicitly requested source implementation and logical review without running tests. No build, lint, CI, provider command, backup copy, recovery or live lab operation is authorized by this document or has been performed for this change.

## Decision before implementation

Continue the actual fetched CloudStack integration commit `f61c4d8198`, including the provider-neutral state foundation `8304bab4c3e8c209de9929c9f718053e32210724`. Preserve the existing Cozystack native recovery adapter at fetched runner commit `c8ad45c4d`. Use immutable CloudStack NAS backups for the current lab replication path. Keep file-backed libvirt incremental capture, LINSTOR, Ceph and array replication distinct provider implementations; an immutable NAS copy must never advertise continuous or low-RPO protection.

The existing foundation has operation journaling and leases but no data transfer or native-provider binding. Retaining it avoids changing CloudStack orchestration or duplicating its API client. The native adapter already supplies preflight, intent-before-submission, async reconciliation and recovered-VM scope checks. The new binding reuses those functions for a single caller-selected backup, retaining the conservative stopped-source and Advanced-destination gates.

The selected source implementation adds a bounded NAS repository copier with explicit disk membership, digest checks, private staging, directory-level publication, immutable receipts and no deletion. It then exposes the copied selected point through the existing `RecoveryProvider` contract. Local mounted repository access is an operator-configured transport boundary: the code does not mount shares, change DNS, claim encryption, or establish cross-site authentication. The destination must already provide durable fsync/atomic-rename semantics and a separately verified repository identity. Those are acceptance gates, not properties inferred from a directory name.

Alternatives considered: direct copying of running VM disks violates consistency and the selected architecture; storage-native replication is preferred when the actual backend provides it but the current lab has no validated provider; raw QMP/NBD would duplicate a lower-level control boundary; libvirt backup/checkpoint APIs are the selected future QCOW2 incremental path but their chain restoration and CloudStack import require a separate provider. This NAS implementation reuses complete native backups and their retained CloudStack metadata instead.

- Cozystack `hack/layersentry/dr_recovery_acceptance.py`: authoritative `preflight`, `submit_once`, `reconcile`, `vm_check` and `Journal` functions; existing acceptance recovers both older/latest fixture points while the binding selects exactly one.

No runtime/version compatibility is inferred from current documentation.

## Trust and failure review

Assets include tenant backup disks, retained backup identity and CloudStack mutation credentials. Caller-supplied object IDs do not establish authority: the native facade requires a trusted authorization callback, exact account/domain/workload/plan/site matching, and the existing authenticated CloudStack preflight. The operator owns repository roots and native module installation; neither is accepted from a browser request. Only explicit NAS disk filenames are copied. Paths, symlinks, file types, inode changes, limits and receipt bindings are checked; payload data and API secrets are not logged. Reusable provider credentials stay inside the native API client.

Copy failures leave private staging for inspection or a bounded rerun. A point is published only after every disk is verified and fsynced; no existing published directory is overwritten. Destination integrity is rechecked before a receipt can authorize recovery. Source retention is external and must be held during replication/recovery; a local lock does not fence CloudStack backup deletion. Source disappearance or metadata change blocks the operation. Older points remain independently retained because this module has no delete/prune action.

Recovery intent is persisted before native submission. A missing async-job reference after submission is ambiguous and is never retried automatically. A completed CloudStack create yields a stopped clone requiring separate destination/application checks; it is not completed disaster recovery. SQLite leases and filesystem locks are single-host coordination, not independent witness or distributed fencing. Planned failover, failback, automatic failover, traffic switching and production enablement remain disabled.

## Implemented entry points and integration contract

- `tools/layersentry/dr_replication.py`: `BackupIdentity` binds the tenant, plan, workload, exact backup, source/destination Sites, repository, native relative path and every disk. `NasReplicator.replicate(identity, guard=...)` copies that immutable full backup; `verify(identity)` rehashes a selected published point and returns its bound receipt. Copy resume reuses verified complete files and rewrites only the service-owned partial file. There is no automatic selection of the newest point and no deletion of retained history.
- `tools/layersentry/dr_native_provider.py`: `NativeNasRecoveryProvider` implements the existing `RecoveryProvider` submit/reconcile interface for one explicit request. Its `replicate()` obtains native API metadata and copies only that selected point. `NativeRecoveryCoordinator.advance()` persists the submission intent and progresses through the existing states to `VALIDATING_DESTINATION` for a scoped stopped clone. Subsequent calls query the recorded job; an ambiguous submission is never replayed.
- Provider construction requires the reviewed native module, its authenticated API client, the existing two-point acceptance fixture, a single-VM plan, Site Pair, selected Recovery Point, replicator, and private journal root. The two fixture points retain the established preflight contract; only the selected UUID is submitted. The existing native adapter is reused without a runner-file modification.
- Enabling the provider requires an integration-owned authorization callback and a verifier proving that CloudStack recovery resolves this actual DR-local repository. Test Recovery additionally requires a trusted verifier of destination network isolation. Missing or negative checks deny the operation. These callbacks are service integration requirements, not implemented witness, authentication, repository-routing or network-isolation services. No permissive default implementations are shipped.
- Each repository root must already contain `.layersentry-repository.json` with exactly `schema: 1`, its `site_id` and the original `repository_id`. This is a pinned operator provisioning marker, not cryptographic remote attestation. Roots must be absolute, free of symlink components, owned by root/current service UID and not group/world writable. Native full backup files must also be owned by root/current service UID; other ownership profiles fail closed until explicitly supported. The current stopped-source native backup path is the intended initial consumer.
- Destination publication requires Linux `renameat2(RENAME_NOREPLACE)` and filesystem support for its atomic semantics. There is no replacing-rename fallback. Private staging stays mode `0700`, including after publication, so the configured native recovery reader must have the corresponding authorized access. All disks and containing directories are fsynced before acknowledgement. Network-filesystem mount timeout, durability and access behavior require later runtime validation; Python deadlines cannot interrupt a kernel filesystem call stuck inside a mount.
- Staging and manifest files contain resource identifiers, sizes and digests, not API secrets or guest file contents. No arbitrary files, source metadata XML, browser URLs or executables are accepted as replication inputs. Operator cleanup of abandoned temporary metadata is separate; it does not trigger source deletion or remove completed points.
