# Native CSI bundle/render design

Status: SOURCE_COMPLETE. Design recorded before implementation; source and local artifact checks below complete. Source-only extension after retained-artifact commit `68fc8b0985`. The exact upstream CloudStack CSI chart and historical sidecar versions remain selected for qualification; no provider upgrade, public image publication, controller/API/UI or live installation is introduced.

The offline renderer uses the vendored, checksum-verified chart from exact upstream `a84477e922d62b82387ab55134fafc9c0b5aaf64` with a checksum-pinned Helm binary. It applies fixed values for an existing credential Secret, cloud-init node metadata, amd64 selectors and a platform-only CSI namespace, then replaces only audited native container image references with exact verified runtime digests. The upstream chart appVersion is 3.0.0 despite chart version 3.0.2; digest replacement prevents that default from selecting the wrong image. An arbitrary chart/values renderer or independent CSI controller was rejected: native chart/RBAC semantics remain upstream-owned and the limited overlay is reviewable.

Primary registry TLS reads bind each exact sidecar tag to its index, linux/amd64 runtime manifest/config and layer descriptors. Each index digest also matches the Kubernetes image-promotion manifest at immutable commit `1ef244cd3da91d917effac12cebdf0d5ef22410e`. Cosign signature manifests are available but cryptographic verification is NOT_TESTED; no SLSA or signature certification is inferred from origin or metadata. Original driver/syncer OCI bytes remain unchanged. Tool Helm is used only for offline local template rendering, not as a live lifecycle owner.

A CSI driver is cluster-wide and privileged on nodes. One driver installation serves a workload cluster bound to one CloudStack project; Kubernetes namespaces are not independent CloudStack project boundaries. The namespace is platform-only, must not be tenant-writable, and needs the privileged Pod Security profile specifically for upstream CSI host mounts. Service accounts and fixed RBAC subjects remain in that namespace; no wildcard grants, cluster-admin binding or broad Secret API read is introduced. The existing Secret must contain cloud-config with exact global.project-id and a least-privileged project credential, validated separately by the trusted runtime owner. The renderer never accepts or emits credentials. Native Cluster/PV/CSI ownership must be checked before applying any cluster-scoped object to avoid adopting an unrelated installation.

The StorageClass syncer remains disabled; no suspended Job is emitted. Its exact image remains in the artifact inventory for a separately reviewed future lifecycle. No StorageClass/default class, PVC, application workload or database is created here; the native resizer capability remains subject to its separate qualification gate. The chart's unconditional expansion flag is therefore not activated.

CSI reads /run/cloud-init/instance-data.json, requires v1.cloud_name=cloudstack and uses v1.instance_id as the CloudStack VM UUID. Its native fallback is a VM-name lookup. The LayerSentry image permits CloudStack/NoCloud/None; successful NoCloud image boot cannot prove this identity path. Node identity remains a deployment gate until each actual CloudStack workload node's metadata UUID matches the native VM/project and CAPI Machine/Node binding. No NODE_ID/providerID is invented. The output is review-only with explicit false qualification and publication gates; the integration lead owns actual apply and live PVC/resize/data-survival verification.


## Source and artifact result

Implemented `native/render.py`, `prepare_images.py` and 17 focused tests. Exact pinned Helm 3.18.6 produced 16 native objects twice with equal output; local Python 3 / PyYAML 5.4.1 was used. Manifest SHA-256 is `5adcfb004bfafa92ae6b0da641cba79448e80e510ac2f50598b3e863ecff775b`. `2026-09-07-native-csi-render-receipt.json` retains the exact input/image binding and every false gate. The renderer checks all 19 upstream chart files and every primary registry metadata digest, including the pinned promotion file. Its only added host-data exposure is the single read-only instance-data JSON file, not the full cloud-init directory.

Collected seven OCI archives into `/tmp/layersentry-csi-native-images-1` (about 158 MiB), preserving the original driver/syncer bytes and actual unsigned provenance/SBOM verification. Five sidecar runtime archives passed compressed SHA-256, descriptor inventory, config platform and uncompressed diff-ID verification. Their exact archive hashes are in `2026-09-07-native-csi-image-receipt.json`; all 58 sidecar layers across the five runtime manifests verified. No image was rebuilt, published, imported into a live runtime or executed. Primary metadata is vendored under `native/registry-evidence`; signature availability remains unverified.

Validation: 17/17 focused tests PASS, including real Helm rendering, credential/reference scoping, RBAC/namespace escapes, unexpected resources, corrupted chart/tool/registry metadata, unpinned image/platform/node identity, writable metadata mount, download integrity/TLS downgrade and false uncompressed layer identity. `crane validate --tarball` was not applicable: that subcommand expects Docker-save manifest.json rather than these OCI-layout archives; the exact OCI graph and layer verifier was used instead. No test result is a live or production acceptance claim.

Deployment remains blocked by the documented native node/project identity and E0 runtime gates. The source image's CloudStack datasource allowance is not a verified workload metadata binding, and NoCloud diagnostic boot evidence cannot substitute for it. The shared release candidate, service/UI, installer and ledger were not edited.
