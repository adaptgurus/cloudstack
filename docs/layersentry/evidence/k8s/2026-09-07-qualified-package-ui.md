# Qualified package UI and operation observation

Status: DESIGN_DEFINED. Base: `526ccf9b69`. Scope: Kubernetes package UI and authenticated JSON client only; no CloudStack core, provider, lab or readiness-gate changes.

The established same-origin Kubernetes BFF remains the authority. The UI consumes the exact `PACKAGE_LIFECYCLE.md` API implemented at the base commit: approved catalog/profile discovery, project-owned cluster status, explicit catalog revision in package requests, and authenticated UNKNOWN-operation observation. Native CloudStack discovery/tenancy and central Flux lifecycle remain unchanged. Direct chart/YAML/credential inputs and an independent UI package controller were rejected because they bypass the approved profile boundary. This is an integration of the existing reviewed API, with no new provider/version or architecture decision requiring a renewed upstream compatibility audit.

The selected cluster gains a package panel showing approved versions/profiles and actual observed status. Catalog availability never means installed or ready. Historical profiles remain selectable for status/uninstall, with install disabled; stateful uninstall stays unavailable. Stateless uninstall requires typing the package name. Create/delete reuse the existing exact-body/idempotency attempt recovery. UNKNOWN observation has its own explicit action: a lost observation response requires a fresh history read before another observation, because that endpoint does not offer mutation-receipt idempotency.

Trust boundaries are the existing authenticated project-scoped BFF and untrusted asynchronous responses. Package/catalog/request scope generations fence project, cluster and profile changes. The client keeps same-origin cookies/CSRF, finite requests, no automatic mutation retry and plain Vue-escaped text. No arbitrary values, charts or credentials enter this UI. Negative tests must cover stale reads, disabled gates/historical installs/stateful deletion, exact confirmation/payload, ambiguous recovery and observation authorization failure. Source tests/build are preliminary evidence; actual served Chrome/Firefox tests on the authorized Rocky deployment remain NOT_TESTED and owned by the integration lead. Rollback is a UI artifact rebuild from the previous reviewed commit; accepted backend operations and journals must be retained.
