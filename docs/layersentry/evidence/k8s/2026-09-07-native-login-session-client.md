# Kubernetes client native login session correction

Exact CloudStack 4.22.1.1 `ApiServlet` marks the session cookie HttpOnly. Native `ui/src/store/modules/user.js` stores the login response session key using the expiring `$localStorage` API and `ACCESS_TOKEN`; `ui/src/api/index.js` reads that token first, with a readable-cookie fallback. The LayerSentry Kubernetes JSON client previously read only the cookie, so a normal authenticated browser could be incorrectly rejected locally before contacting the BFF.

The client now follows the existing native token lookup and keeps its same-origin JSON/header boundary, redirect rejection, authorization errors and mutation idempotency controls. No CloudStack backend, cookie security, token persistence, tenancy authority or session lifetime changes. Tests prove normal login without a readable cookie, current token precedence, missing-session rejection and existing API/UI regressions: 34 tests in two focused suites passed. Full artifact CI and exact-artifact Rocky browser validation are pending. Reverting the narrow client change restores prior behavior; no new data migration or runtime credential storage exists.
