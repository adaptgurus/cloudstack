GUI run `34044594517` remains FAILED on both browsers/hosts and identifies the rejected command as `logout`, HTTP 431. Native `ApiServlet.java` rejects logout with `Session not found for the logout process.` when no session exists. UI `login`/`oauthlogin` issued logout without awaiting or handling its promise. Separately, disabled `forgotPassword` POST discovery returned 401, but the interceptor recognized optional probes only in GET params and could dispatch a global logout during login. A password-authenticated shell also queried SAML account switching and received 432. These observations support a narrow UI-only correction: serialize logout before login, tolerate only the exact native missing-session response, recognize username-free discovery in GET/POST, and query SAML accounts only for a SAML session. No backend error codes, session validation or RBAC semantics change. Actual reset requests containing a username remain subject to normal authorization handling.

Alternatives rejected: suppressing all browser errors, ignoring all logout failures, disabling native authentication checks or changing core APIs. Exact checked-out 4.22.1.1 source is authoritative; [versioned SAML authentication documentation](https://docs.cloudstack.apache.org/en/4.22.0.0/adminguide/accounts.html) provides adjacent release context only.
