# Product UI completion decision

Base: `ebd08bae2fcd3311bf0f4f4af5fc28cdf136f125`. Scope: Workstream A presentation only. Validation: `NOT_TESTED`, following the user's code-first instruction. No deployment or shared-ledger writes.

The existing Quick Provision, persona dashboards, native action definitions and LayerSentry design tokens remain the foundation. The remaining shared inventory/detail surface uses transient errors, sometimes dereferences a missing HTTP response, and can accept stale list requests. OAuth verification renders an empty page. Dashboard activity failures can render as empty feeds. These gaps affect multiple product sections through shared components.

Decision: extend the existing generated view with a contextual page identity and persistent read-state component, request-generation guards, safe diagnostic summaries, and retry of reads only. Keep every existing action object, parameter builder and native async mutation flow. Complete visible-tab/empty-detail handling, dashboard feed failure states, and authentication accessibility. Backend-dependent DR and managed-service routes remain owned by their real service contracts; the file-replication operator CLI is not a browser API.

Evidence: exact local CloudStack 4.22.1.1 `ui/src/views/AutogenView.vue`, `components/view/ResourceView.vue`, `utils/request.js`, route definitions and Workstream A handoff. The [4.22.1.0 documentation index](https://docs.cloudstack.apache.org/en/4.22.1.0/) provides the adjacent published documentation family, not proof of patch-specific behavior. Upstream [issue 5300](https://github.com/apache/cloudstack/issues/5300) illustrates why a brief list failure is insufficient; it is historical context, not a reproduced current defect. [Issue 5652](https://github.com/apache/cloudstack/issues/5652) reinforces session-bound async state; this change does not alter mutation job storage. Research queried CloudStack UI error/list/async routing history. No new provider architecture is proposed, so XaaS and a replacement backend are not applicable.

Alternatives: duplicating each native page multiplies rebase and action-preservation risk; replacing API error handling globally could change login/session semantics. Shared presentation plus local read guards has the narrower impact. Risks: route-specific list shapes, project switches, delayed reads and tabs gated by network services. Manual review covers these paths; the later test gate must cover all four personas, empty/error/partial states, overlapping reads, deep links, action identity, Chrome/Firefox and exact Rocky artifact deployment. Revert this isolated UI commit to roll back; no schema or runtime migration exists.
